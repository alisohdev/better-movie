## Database idle observation

Agent database/API traffic stopped at 13:48:30 UTC. The read-only probe began at 13:54:51 UTC, after 6 minutes 21 seconds. Connections closed after each probe. The existing pooled URL used `verify-full` TLS; the only query was `SELECT 1, pg_postmaster_start_time()`.

PostgreSQL start time changed from 13:39:44 UTC before idle to 13:54:55 UTC afterward. This establishes a compute restart during the quiet interval, consistent with scale-to-zero. The first after-idle connection took 1,590.686 ms to connect and 1,928.234 ms including the successful query. Five following fresh connections had a median of 1,319.925 ms including query, range 1,251.329–1,338.509 ms. This measures the connection path after restart, including WAN, TLS, authentication, and pooler overhead; it does not isolate pure server wake-up milliseconds. There is one restart observation, not a cold-latency distribution.

The Go API was then measured with Neon already awake: first health 995 ms, followed by five health responses with median 213 ms and range 208–393 ms. All were HTTP 200 and edge MISS. Function recycling is unobserved; the first response remains a cold-function candidate, not a certified isolated Go startup measurement. The before/after database samples and API headers are retained in the raw evidence.

## Limits and remaining work

Mobile lab LCP exceeds the 2.5-second planning target and needs a focused trace before changing rendering or payload behavior. CLS and the 150 KiB JavaScript ceiling pass in this lab. These samples do not establish field p75, INP, Iranian-network accessibility, catalog scalability, or a comparative speedup. HTTP timing cannot attribute WAN, Go initialization, SQL, and pooler costs independently; no Server-Timing data is emitted. A first request is not proof of a cold Go process.

No production deployment, paid resource, Neon migration/reseed, provider scraping, accounts, AI, Redis, service worker, or global Codex configuration change was made. Preview protection remains enabled. Generated Neon skills, skills-lock.json, environment files, and auth artifacts are ignored and untracked. Missing-environment deployment behavior, concurrent connection counts, account eligibility, and regional access remain open.
