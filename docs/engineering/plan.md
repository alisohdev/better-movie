# First vertical slice execution plan

The user-approved scope ends at one working bilingual synthetic discovery slice and a prioritized next-step list. It does not authorize building every roadmap feature in one run.

## Definition of done

A production Astro build serves useful English and Persian HTML. A React discovery island requests PostgreSQL-backed Go results with genre inclusion, exclusion, any/all mode, year, runtime, sorting, pagination, and restorable URL state. Details and Back navigation work. Invalid filters do not broaden the query. Synthetic content is labeled and cannot imply real availability. Meaningful tests and desktop/mobile browser checks pass. Deployment results are labeled local, remote, or unverified.

## Phases

1. Reconcile requirements and preserve useful data-source research.
2. Compare two structurally distinct architectural candidates, use an independent native judge, and record the selected design.
3. Prove static Astro, a portable Go handler, and a real PostgreSQL connection locally. Attempt only eligible free remote infrastructure with available credentials. Record any missing account or database access precisely.
4. Implement a bounded synthetic slice. Keep PostgreSQL authoritative for live results and use the same owned fixture revision for prerendered details.
5. Validate SQL/domain behavior, query-state round trips, browser flows, responsive design, cache/prefetch behavior, and honest lab performance evidence.
6. Document local setup, free deployment steps, actual results, blockers, and the next small increments.

Throughput checkpoint: one backend, one frontend, one database, one synthetic catalog, and one slice. Architecture candidates and hosting research are independent. Implementation waits for their synthesis. PostgreSQL/Go and frontend tasks may run independently against an agreed contract. No external model providers are used.

- Blocking first steps. Reconcile the two briefs, complete architecture candidates and the separate judge, freeze the wire contract, then establish the local database.
- Independent workstreams. Backend owns Go, SQL, migrations, and backend tests. Frontend owns apps/web, npm configuration, and frontend unit tests. Parent owns integration/browser verification, deployment evidence, and documentation.
- Shared mutable state. No worker shares a writable source file. Parent alone owns the fixture, API contract, and deployment configuration. Agents have named file ownership, not an operating-system sandbox.
- Smallest safe decomposition. Two implementation owners keep the Go/SQL and Astro/React work separate while a fixed JSON contract allows integration. A deployment spike is verified before advancing each owner into the full slice.

## Gates and constraints

The effective parent sandbox is danger-full-access and approval policy is never. Native Codex agents inherit it. The pstack bounded setting provides no native confinement. Check this before each development workflow. All configured model work uses native GPT-6.1 Sol at max effort.

No paid service, real-data ingestion, global configuration change, provider integration, AI dependency, or fabricated deployment success. A missing remote credential does not prevent locally verified work. It does prevent claiming an end-to-end remote deployment.

The decision trail is `.audit/vertical-slice.tsv`. Verification evidence belongs in `docs/verification/` and generated local artifacts stay out of source control.
